Energy Copilot: from public data to a defensible energy prospect

A map-first product for finding photovoltaic opportunities in Luxembourg, applying public tenders and answering cited questions about tariffs and law. The architecture keeps model reasoning useful while moving consequential calculations, access control and evidence into deterministic services.

Le déploiement public est hors ligne ; cette page documente l’architecture, les décisions, les contrôles, les preuves et les limites.

Status: the live deployment is offline. energy.soufien.lu, its API and its telemetry are not served at the time of writing (31 October 2026). This page documents the architecture as it was built and measured in July and August 2026; it makes no claim about uptime today. The code, the decision records and the evaluation evidence are public: github.com/SFHAJJI/energy-copilot (Apache-2.0).

Repository description: Production Azure AI co-pilot for Luxembourg solar-PV prospecting: geospatial data, tenders, deterministic tariffs, RAG and MCP law. Topics: agentic-ai, azure-openai, luxembourg, maplibre, mcp, postgis, rag, solar-energy, terraform.

What was built, and what it proves

Business problem

Solar, tender, price and legal data is public but fragmented and difficult to turn into a prospect a developer can act on.

Product answer

One map combines roofs and sites, tender applicability, economics and a cited assistant.

Engineering answer

Scheduled Python producers feed PostGIS/pgvector; a bounded .NET agent composes five tools.

Trust answer

Numbers come from code, legal evidence from Lex MCP, SQL is read-only and unsupported answers are refused.

Scope of the claim. "Production" meant publicly deployed, monitored and continuously delivered while it ran. It never meant enterprise traffic, a formal SLA or regulated approval; those gaps are listed below. Today it is offline.

01 · The model plans; bounded services decide

The online path is deliberately small. The model can select tools and explain outputs, but it cannot write data, calculate a tariff or order the interface to display unsupported results.

01React + MapLibreMap, candidate rail, tenders, streamed tool trace, citations and export.
02.NET agent hostAzure OpenAI tool calling, three-round cap, validation, refusal and SSE.
03Five bounded toolsSQL, law, corpus search, tariff calculation and tender retrieval.
04Authoritative servicesPostGIS/pgvector, tariff engine, public sources and temporal law through Lex MCP.

Safety boundary: tool output, not model prose, drives map pins and cards. Typed payloads are validated; the AI explains evidence but does not become the evidence.

sql

Read-only analysis and geo candidates; the exact query is provenance.

law

Dated Luxembourg and reviewed EU text through the public Lex MCP server.

search_corpus

Hybrid retrieval over current energy documents in PostgreSQL.

compute_tariff

Typed inputs into deterministic code; the model never calculates.

find_offers

Current tenders and machine-checkable applicability constraints.

Request lifecycle: one question, five visible stages

  1. Normalize and route. The host supplies schemas and bounded tools.
  2. Call tools, sometimes in parallel. Geo and dated-law lookups can run together.
  3. Validate outputs. Database role, bouncer, timeouts, caps and contracts.
  4. Ground or refuse. No usable evidence produces a refusal.
  5. Render deterministically. Payload shape produces pins, cards or text.

Azure delivery plane: small because one engineer operates it

Static Web Apps served the client. Container Apps ran the API. PostgreSQL Flexible Server owned relational, geospatial and vector data. Azure OpenAI handled chat and vision; Content Understanding extracted tender constraints. Terraform defines infrastructure; GitHub Actions deploys through OIDC.

A second search store or more agents must earn their operating cost through measured need.

02 · Batch producers create reusable facts

Ingestion does expensive interpretation once. Requests read typed, provenance-carrying rows rather than repeatedly asking a model to rediscover structure.

Official and public sources

  • National INSPIRE buildings + solar cadastre
  • TED and Luxembourg tenders
  • PVGIS, prices, tariffs and aid
  • Grid-operator documents + public Lex MCP

Python producers

  • Coordinate transforms + geometric joins
  • Three-class existing-PV vision
  • Content Understanding extraction
  • History, provenance and fail-loud status

PostgreSQL consumers

  • PostGIS roofs, parcels and materialized sites
  • Offers and typed constraints
  • FTS + pgvector document chunks
  • Read-only API tools and map endpoints

National buildings became the primary source

The first design used the solar cadastre and silently missed large industrial roofs. National building polygons now lead; the cadastre is a nullable suitability signal joined spatially. Unknown remains unknown.

Vision with abstention: yes / no / maybe

Ambiguous roofs stay maybe; an outage leaves the field null. Every downstream surface preserves that distinction.

Documents become filterable predicates

Content Understanding stores verbatim text plus typed constraints. "Apply tender" is deterministic filtering, not query-time invented eligibility.

Two retrieval responsibilities

The current energy corpus uses PostgreSQL FTS + pgvector with rank fusion. Legal search is not duplicated: Lex provides dated Luxembourg and EU law, history, comparison and provenance.

Key lesson. Data-source quality mattered more than model sophistication. Replacing the wrong roof source improved the product more than adding another model or search service would have.

03 · Controls sit where the failure happens

Prompt instructions help, but consequential controls are enforced in code, database permissions, typed contracts or deployment gates.

FailureControlResidual risk
Fabricated tariffDeterministic engine + C#/Python parity; model only extracts and narrates.New formulas require code; uncovered questions are refused.
Unsafe database accessanalyst_ro role, forbidden-column bouncer, timeout and row cap.A permitted SELECT may still be slow, wrong or infer data.
Confident false absenceZero rows trigger witness queries and an explicit diagnosis.Main and witness queries can share a wrong assumption.
Ungrounded proseSession-wide evidence guard; the judge sees actual rows, not citation labels.Rendered rows have no separate prose-grounding score.
Wrong UI actionTyped payload shape drives pins and cards; no model render tool.Bad aliases and coordinates still need validation.
Hidden uncertaintyVision abstains to maybe; estimates and unknowns remain labelled.A human must confirm ambiguous roofs.

AI governance

The interface identifies the AI. It provides research support, not automated decisions about people. Legal and monetary answers are cited or refused; inferred labels require confirmation.

Privacy

No account or profile is required. Conversation turns support bounded continuity and are inaccessible to the analytical role. Inputs are not used for fine-tuning. A formal notice and erasure path remain gaps.

Cloud identity

GitHub deploys through OIDC. Runtime credentials are Container App secrets; the PostgreSQL bootstrap password remains in protected Terraform state. Managed-identity runtime auth is the next hardening step.

Network

HTTPS, a restricted CORS allowlist and a PostgreSQL firewall were live. Private endpoints, VNet integration, per-user authorization and retrieval ACLs are not.

06 · A credible personal production system, not enterprise theatre

Real when it ran

  • Public deployment and live telemetry
  • Automated pipelines with freshness status
  • Read-only and deterministic tool boundaries
  • Terraform, OIDC and tested CI/CD
  • Measured model and retrieval choices
  • Visible abstention, refusal and provenance

Enterprise adoption adds

  • Entra runtime identity, private endpoints and VNet
  • Per-principal authorization and retrieval ACLs
  • Purview-class catalog, retention and lineage governance
  • DPIA, model-risk approval and security review
  • SLOs, load tests, on-call and disaster recovery
  • Segregation of duties and release approvals

The last row is not theoretical: the public deployment is offline today, which is exactly what a cost guard on a personal subscription does. Lex, the legal corpus this product consumed, is online and documented separately.

The signal is judgment, not service count

This demonstrates problem framing, data engineering, bounded agent design, RAG, Azure delivery, evaluation and honest risk ownership. The strongest choices are the capabilities deliberately left out until evidence makes them worth operating.
